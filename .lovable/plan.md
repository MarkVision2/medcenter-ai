## Что сделаем

Заменим "WhatsApp" CTA-кнопки на кнопки **"Записаться на диагностику"**, которые открывают форму. Добавим секцию **"Бронирование диагностики"** с формой (Имя, Телефон, Название клиники, Ниша/направление, чекбокс согласия). После отправки формы:
1. Данные сохраняются в БД (Lovable Cloud).
2. Срабатывает событие **Lead** в Meta Pixel + Conversions API (с email/phone хешированием для лучшего matching).
3. Дублируется в CRM/Таблицу (HubSpot — через коннектор, опционально, или Google Sheets).
4. Пользователя редиректит на новую страницу **/thank-you** с сообщением "Заявка принята!".
5. На странице "Спасибо" — текст про быструю запись + кнопка WhatsApp с предзаполненным сообщением, куда подставлены данные из формы.

## Технические детали

### 1. БД (миграция)
Таблица `public.diagnostic_leads`:
- `id uuid pk default gen_random_uuid()`
- `name text not null`
- `phone text not null`
- `clinic text not null`
- `niche text not null`
- `source text default 'landing'`
- `user_agent text`, `referrer text`, `fbp text`, `fbc text`
- `created_at timestamptz default now()`

RLS включён. Политики:
- **INSERT для anon/authenticated**: разрешено (публичная форма).
- **SELECT**: запрещён всем (только сервис-роль через edge functions).

### 2. Edge Function `submit-diagnostic-lead`
- Принимает данные формы, валидирует через Zod (имя 2-100, телефон normalize, клиника 2-200, niche из enum, agreement=true).
- Записывает в `diagnostic_leads` через service-role клиент.
- Вызывает Meta CAPI событие **Lead** с хешированными `ph` (phone) и `fn` (имя) для лучшего matching + `event_id` для дедупликации с браузерным Pixel.
- Возвращает `{ success: true, event_id }`.

### 3. Обновление `meta-capi-lead`
Расширим, чтобы принимать `ph`, `fn`, `clinic` в `custom_data` (хешируем PII перед отправкой).

### 4. Компонент `DiagnosticForm.tsx`
- React Hook Form + Zod resolver.
- Валидация: имя required, телефон required (маска `+7 (___) ___-__-__`, IMask или простая regex), клиника required, ниша required, чекбокс required.
- При submit:
  1. Генерируем `event_id` (UUID).
  2. Срабатывает `fbq('track', 'Lead', {...}, {eventID})` в браузере.
  3. POST в edge function `submit-diagnostic-lead` (передаём данные + event_id + fbp/fbc).
  4. При успехе: сохраняем `{name, phone, clinic, niche}` в `sessionStorage` и `navigate('/thank-you')`.
  5. При ошибке: toast с понятным сообщением.

### 5. Страница `ThankYou.tsx` (route `/thank-you`)
- Читает данные из `sessionStorage`.
- Формирует WhatsApp URL с предзаполненным текстом (encodeURIComponent).
- Если данных нет — показывает базовый текст и кнопку без подстановки.

### 6. Замена существующих CTA
Заменим обе `<WhatsAppButton />` на лендинге (hero и финал) на кнопку "Записаться на диагностику", которая делает `scrollIntoView` к секции формы (`#diagnostic-form`). Сам компонент `WhatsAppButton` оставим — он будет переиспользован на странице "Спасибо".

### 7. CRM (опционально — спросим в реализации)
По умолчанию данные сохраняются в БД. Если нужна интеграция с **HubSpot** или **Google Sheets** — потребуется подключить коннектор отдельно. На этом этапе делаем БД + Meta CAPI; CRM-интеграцию добавим следующим шагом, если нужно.
